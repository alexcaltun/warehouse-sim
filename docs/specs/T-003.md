# T-003 - Alocatori: Hungarian si FIFO
Owner: agy | Fisiere permise: sim/allocator/hungarian.py, sim/allocator/fifo.py, tests/test_allocator.py

## Context
`NearestAllocator` din sim/baseline.py e lacom: fiecare robot ia cel mai apropiat
task. Are doua defecte masurabile pe care acest task le ataca:
- nu e optim global (suma distantelor poate fi mai mica cu alta repartizare);
- infometeaza task-urile departate, care asteapta la nesfarsit.

Implementezi doi alocatori alternativi. Amandoi respecta protocolul `Allocator`
din sim/core/types.py. NU modifici NearestAllocator.

## A. sim/allocator/hungarian.py
class HungarianAllocator:
    name = "hungarian"
    def assign(self, robots, tasks, grid, t) -> dict[str, str]

Repartizare optima global: minimizeaza SUMA distantelor Manhattan robot -> task.pickup.
Implementezi algoritmul maghiar (Kuhn-Munkres), O(n^3), doar cu stdlib.
Matricea e dreptunghiulara (numarul de roboti difera de cel de task-uri):
o completezi cu o valoare mare constanta pana devine patrata, iar perechile
artificiale NU apar in rezultat.
Daca sunt mai multe repartizari optime, alegi deterministic: sortezi robotii si
task-urile dupa id inainte de a construi matricea.

## B. sim/allocator/fifo.py
class FifoAllocator:
    name = "fifo"
    def assign(self, robots, tasks, grid, t) -> dict[str, str]

Task-ul cel mai vechi primeste primul un robot. Ordonezi task-urile dupa
(released_at, id) crescator; fiecare, in ordine, merge la cel mai apropiat robot
liber ramas (departajare dupa id robot). Garanteaza ca niciun task nu e infometat.

## Reguli comune
- Returnezi doar perechi valide: robot fara task, task neasignat.
- Un robot apare o singura data; un task apare o singura data.
- Liste goale la intrare => dict gol la iesire, fara exceptii.
- Fara librarii externe. Fara scipy.

## Teste (tests/test_allocator.py)
Compari toti trei alocatorii (NearestAllocator din sim.baseline inclus).
- Fiecare: dict gol pentru roboti=[] si pentru tasks=[].
- Fiecare: niciun robot si niciun task nu apare de doua ori in rezultat.
- Fiecare: cu 3 roboti si 5 task-uri => exact 3 perechi; cu 5 roboti si 3 task-uri
  => exact 3 perechi.
- Hungarian: construieste un caz mic (2 roboti, 2 task-uri) unde alegerea lacoma
  da o suma mai mare decat cea optima, si verifica explicit ca Hungarian gaseste
  suma minima iar NearestAllocator nu. Acesta e testul central al task-ului.
- Hungarian: determinism - doua apeluri identice dau acelasi dict.
- FIFO: cu trei task-uri cu released_at 5, 1, 3 si un singur robot, se aloca
  cel cu released_at 1.
- Toti: ruleaza o simulare completa pe make_warehouse(20,20) cu AStarPlanner si
  10 roboti / 30 task-uri, pentru fiecare alocator, si verifica tasks_done == 30.
